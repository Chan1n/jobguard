# บันทึกการใช้ AI — 27 ตุลาคม 2026

## เครื่องมือและขั้นตอนที่ใช้จริง

ใช้ Codex อ่านแผนที่ผู้ใช้แนบ สร้าง Next.js/TypeScript/CSS และทดสอบด้วย Node test runner + tsx ใช้ Image Gen สร้างแนวทางหน้าจอ (`design-concept.png`) และ in-app browser ตรวจหน้าจอ/กรอก URL/เลือกไฟล์จำลอง/บันทึกการตัดสินใจ/โหลดใหม่ ใช้เว็บและ GitHub API ตรวจแหล่งข้อมูล ใช้ npm ติดตั้ง dependencies ไม่มี AI API ในเว็บที่ส่งมอบ

Prompt แนวทางภาพ: “Full primary desktop screen JobGuard Thai browser-local cybersecurity tool for students checking job recruitment URLs and files ... white/offwhite #f6f8fa, navy #14283f, teal #087e8b ... two tabs ... URL textarea ... before-decision guidance ... history ... native CSS feasible UI, no fake stats, no gradients.” ใช้ built-in Image Gen ไม่ใช้ภาพเป็นหน้าจอเว็บจริง

ตัวอย่างข้อกำหนดสำคัญที่ AI ใช้: ต้องคงความต่าง HTTP/HTTPS/path/query, ห้ามเหมารวมทั้งโดเมน, PE ต้องตรวจ offset/signature ในขอบเขต, ไม่เก็บ URL เต็มในประวัติ และห้ามอ้างการทดสอบมัลแวร์จริง

## การตรวจแก้ที่เกิดขึ้นจริง

- แก้คำสั่งทดสอบจาก tsx CLI เป็น `node --import tsx --test` เพราะ CLI สร้าง IPC ไม่ได้ในสภาพแวดล้อมจำกัด
- ตรวจพบว่าการตัดเครื่องหมายท้าย URL อาจเปลี่ยน query/path จึงแก้ให้รักษา URL และเพิ่ม assertion
- แก้ล้างประวัติให้ล้างผลที่กำลังแสดงด้วย ป้องกันการเลือกการตัดสินใจในรายการที่ไม่มีประวัติแล้ว
- Build สำเร็จและทดสอบตรรกะ 11 กรณีผ่าน ดูหลักฐานใน `evidence/`
- ใช้ probe เฉพาะ build สำหรับวัด Resource Timing ระหว่างตรวจ URL/ไฟล์ แล้วคืน HTML เดิมก่อนส่งมอบ ไม่ใช่ฟีเจอร์เว็บ

## สิ่งที่ผู้สมัครกำหนด และสิ่งที่ยังต้องตรวจเอง

ผู้ใช้เป็นผู้ให้แผน ขอบเขต แหล่งข้อมูล และเกณฑ์ส่งมอบ ส่วน AI เป็นผู้เลือกวิธีลงโค้ดและตรวจทดสอบในรอบนี้ **ยังไม่มีหลักฐานว่าผู้สมัครตรวจโค้ดหรืออนุมัติการออกแบบด้วยตนเอง** จึงไม่อ้างว่าเกิดขึ้นแล้ว

ก่อนนำส่ง ผู้สมัครควรอ่านตรรกะ normalize/PE/ประวัติ ตรวจ licenses และที่มา ทดลองรันด้วยตนเอง ยืนยันข้อจำกัดและอธิบายผลทดสอบได้ รวมทั้งเลือกว่าจะใช้แผนกิจกรรมและงบที่เสนอหรือปรับอย่างไร
