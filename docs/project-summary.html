ตรวจเบื้องต้นก่อนกด ก่อนรัน

ต้นแบบช่วยนักศึกษาและเด็กจบใหม่พิจารณาลิงก์และไฟล์จากการสมัครงาน ก่อนเปิดหรือรัน พร้อมหลักฐาน ข้อจำกัด และการบันทึกการตัดสินใจ

ปัญหาและกลุ่มเป้าหมาย

ผู้สมัครงานอาจได้รับลิงก์หรือไฟล์จากผู้ติดต่อที่ยังไม่รู้จัก และไม่ทราบว่าควรตรวจอะไรต่อ โครงการมุ่งนักศึกษาและเด็กจบใหม่ 60 คน รองรับทั้งมือถือและคอมพิวเตอร์ สมมติฐานเรื่องความต้องการและความเข้าใจยังต้องตรวจสอบ ต้นแบบนี้ใช้สถานการณ์จำลอง ยังไม่มีการสัมภาษณ์หรือผลทดลองกับผู้ใช้จริง

ทางเลือกและเหตุผลที่เลือก

ทางเลือก ข้อดี ข้อจำกัด
คู่มือ / Checklist ทำง่ายและดูแลน้อย ผู้ใช้ต้องตรวจทุกอย่างเอง
เว็บตรวจเทียบข้อมูลภัยในเครื่อง มีผลเฉพาะรายการและหลักฐาน
ไม่ต้องส่งไฟล์ออกไป		 ขึ้นกับความครอบคลุมและความใหม่ของข้อมูล

เลือกเว็บตรวจเทียบในเบราว์เซอร์ และใส่ Checklist ในหน้าจอ เพื่อช่วยฝึกอ่านหลักฐานและเลือกการกระทำต่อ ผู้ใช้ยังต้องยืนยันกับบริษัทผ่านช่องทางที่ค้นหาเอง

กระบวนการหลัก

เลือก URL หรือไฟล์ → ตรวจในเบราว์เซอร์ → อ่านผลและข้อจำกัด → บันทึกการตัดสินใจ → ดูประวัติ

ขอบเขตและหลักการออกแบบ

  • URL: HTTP/HTTPS สูงสุด 5 ลิงก์ เทียบ URL เต็ม ไม่เหมารวมทั้งโดเมน ไม่เปิดปลายทาง ไม่ตาม redirect และไม่วิเคราะห์ความหมายข้อความ
  • ไฟล์: ไม่เกิน 20 MB คำนวณ SHA-256 ตรวจชนิด PDF, JPEG, PNG และ Windows PE ไม่เปิด รัน แตกไฟล์ หรืออัปโหลด
  • ผลตรวจ: พบรายการ / พบข้อควรระวัง / ไม่พบรายการ / ตรวจได้บางส่วน พร้อมที่มาและวันที่ข้อมูล
  • ประวัติ: ใน localStorage สูงสุด 100 รายการ ไม่เก็บ URL เต็ม ชื่อไฟล์ ข้อความแชท หรือไฟล์ เก็บรหัสแฮชเพื่อจำรายการซ้ำ
ไม่พบรายการ ไม่ได้แปลว่าปลอดภัย
เครื่องมือตรวจสอบเบื้องต้น ไม่รับรองความปลอดภัยและไม่วิเคราะห์พฤติกรรมมัลแวร์

ต้นแบบและแผนดำเนินงาน

สิ่งที่ทำได้จริง

Next.js / TypeScript ตรวจทั้งหมดในเบราว์เซอร์ รันผ่าน localhost หลังติดตั้ง dependencies ได้ แยกส่วนตรวจ URL ไฟล์ ข้อมูลภัย และประวัติ บันทึกการตัดสินใจและแก้ย้อนหลังได้ แจ้งรายการซ้ำและข้อผิดพลาดการจัดเก็บ ส่งออกเว็บสแตติกได้

ข้อมูลจริง: Phishing.Database 5,000 URL (เรียงและเลือกชุดย่อย) และ SHA-256 41 รายการจาก ESET DeceptiveDevelopment สำเนา 27 ต.ค. 2026 พร้อม commit / metadata และ MIT / BSD-2-Clause ในโปรเจกต์ ข้อมูลทดสอบแยกต่างหาก ไม่มีตัวอย่างมัลแวร์

ผลทดสอบและหลักฐาน

Unit tests 11 กรณีผ่าน และ build สำเร็จ ตรวจจริงใน in-app browser: URL ตรงสำเนาและไม่ตรงสำเนา, ช่องว่าง, ตรวจซ้ำ, บันทึกแล้วโหลดใหม่, ไฟล์ PE จำลองนามสกุล PDF และไฟล์ข้อความ ตรวจมือถือจำลอง 390 px ไม่ล้นแนวนอน Resource Timing ในการตรวจ URL/ไฟล์ที่ทดสอบไม่พบคำขอใหม่หลังเริ่มตรวจ

หลักฐาน: docs/evidence/ และ docs/test-results.md ทดสอบแฮชมัลแวร์เป็นการจับคู่ค่าจากฐาน แยกจากทดสอบการคำนวณแฮช ไม่อ้างการทดสอบมัลแวร์จริงครบเส้นทาง

แผนโครงการ 6 สัปดาห์

ช่วง กิจกรรม
สัปดาห์ 1 ประเมินก่อนเรียน แนะนำเครื่องมือ
สัปดาห์ 2–3 ฝึกอ่าน URL ชนิดไฟล์ แฮช และสถานการณ์จำลอง จบกิจกรรมหลัก
สัปดาห์ 4–5 ติดตามการนำไปใช้อย่างน้อย 14 วันหลังจบกิจกรรมหลัก
สัปดาห์ 6 ประเมินหลังเรียน สรุปผลและข้อเสนอปรับปรุง

ทีม 3 คนดูแลการเรียนรู้ เครื่องมือ และติดตามผล แบ่ง 3 กลุ่ม กลุ่มละ 20 คน ใช้สถานการณ์จำลองสำหรับ executable ไม่บังคับดาวน์โหลดไฟล์เสี่ยง ติดตามผ่านแบบบันทึกแยกจากเว็บ ไม่ส่ง URL ไฟล์ หรือข้อความส่วนตัวให้ทีม

การวัดผลและงบประมาณเสนอ

ประเมินแปลผลและเลือกการกระทำพร้อมเหตุผลก่อน–หลัง เป้าหมายเบื้องต้น: อย่างน้อย 80% ตอบถูกอย่างน้อย 4 จาก 5 สถานการณ์ ปรับเป้าหมายหลังเห็นก่อนเรียน จำนวนการตรวจไม่ใช่จำนวนภัยที่ป้องกันได้

งบประมาณ 30,000 บาท: วิทยากร 8,000 / สถานที่และอินเทอร์เน็ต 5,000 / เช่าอุปกรณ์ 6,000 / สื่อ 2,000 / กิจกรรมและติดตาม 4,000 / สำรอง 5,000 เป็นประมาณการ ไม่รวมเงินเดือนทีมหลัก ยังไม่ใช่ราคายืนยัน

ข้อจำกัดและงานต่อยอด

ชุดข้อมูลไม่ครอบคลุมภัยทั้งหมดและไม่อัปเดตอัตโนมัติ แฮชเปลี่ยนเมื่อเนื้อหาเปลี่ยน ตรวจชนิดเป็นเพียงโครงสร้างพื้นฐาน ไม่ยืนยันไฟล์สมบูรณ์ ยังต้องทดสอบมือถือจริง/หลายเบราว์เซอร์/ไฟล์ 20 MB เพิ่มเติม ยังไม่มีผลจากผู้เข้าร่วมจริง งานต่อยอด: เพิ่มแหล่งข้อมูล ระบบอัปเดต ชนิดไฟล์ การส่งออกไม่ระบุตัวตน และการเปิดเว็บใหม่แบบออฟไลน์
